# Software Engineers API

A small Spring Boot REST API backed by PostgreSQL running in Docker Compose.
Built while following the Amigoscode Spring Boot course.

`GET /api/v1/software-engineers` returns software engineers stored in Postgres,
mapped with Spring Data JPA.

## Tech stack

| Component | Version |
|---|---|
| Java | 21 |
| Spring Boot | 4.1.1 |
| Spring Data JPA (Hibernate) | via `spring-boot-starter-data-jpa` |
| PostgreSQL | 18 (Docker image `postgres:latest`) |
| Build | Maven Wrapper 3.9.16 |

## Prerequisites

- JDK 21
- Docker with Compose v2 (`docker compose`, not `docker-compose`)

No local Maven or Postgres install is needed — the Maven Wrapper and Docker cover both.

## Quick start

```bash
git clone https://github.com/OmarNizam/spring-boot.git
cd spring-boot
./mvnw spring-boot:run
```

That's it. Spring Boot's Docker Compose support reads `compose.yaml`, starts the
Postgres container automatically, and points the datasource at it. Hibernate creates the
schema on first run and `DataSeeder` inserts two sample engineers.

Then:

```bash
curl -s localhost:8080/api/v1/software-engineers | jq
```

```json
[
  { "id": 1, "name": "James",  "techStack": ["js, node, vue, java, spring boot"] },
  { "id": 2, "name": "Jamila", "techStack": ["js, node, vue, python, FastApi"] }
]
```

## Running

### Option 1 — `spring-boot:run` or your IDE (recommended for development)

```bash
./mvnw spring-boot:run
```

Postgres is started for you and **left running** when the app stops
(`spring.docker.compose.lifecycle-management=start-only`).

### Option 2 — executable jar

```bash
docker compose up -d db     # start Postgres yourself first
./mvnw package
java -jar target/spring-boot-0.0.1-SNAPSHOT.jar
```

Docker Compose support is deliberately excluded from the repackaged jar by
`spring-boot-maven-plugin`, so the jar does **not** start Postgres — it connects using the
`spring.datasource.*` properties in `application.properties`. Start the database first.

### Option 3 — everything in Docker

```bash
docker compose --profile full up --build
```

The `app` service sits behind the `full` compose profile. Without that flag,
`docker compose up` starts only the database — which is what you want during development,
so the app image isn't rebuilt on every run.

## API

Base URL: `http://localhost:8080`

| Method | Path | Description | Response |
|---|---|---|---|
| `GET` | `/api/v1/software-engineers` | All software engineers | `200` — JSON array |
| `GET` | `/` | Demo endpoint on `Application` | `200` — `3` |

`requests.http` in the project root contains both calls, runnable directly from
IntelliJ's HTTP client.

### `SoftwareEngineer`

| Field | Type | Notes |
|---|---|---|
| `id` | integer | Generated by Postgres (identity column) |
| `name` | string | |
| `techStack` | array of strings | Stored in the `software_engineer_tech_stack` side table |

## Database

| Setting | Value |
|---|---|
| Host port | **5332** (container port 5432) |
| Database | `postgres-spring-boot` |
| User / password | `amigoscode` / `password` |
| Container | `postgres-spring-boot` |
| Volume | `postgres_data` (data survives `docker compose down`) |

> The credentials above are local development values, committed intentionally so the
> project runs after a clone. Do not reuse this setup as-is for anything deployed.

Inspect the data directly:

```bash
docker exec -it postgres-spring-boot psql -U amigoscode -d postgres-spring-boot

\dt
select * from software_engineer;
select * from software_engineer_tech_stack;
```

Schema is managed by Hibernate (`spring.jpa.hibernate.ddl-auto=update`) — tables are
created and evolved from the entity classes. There are no migration files.

Start over from an empty database:

```bash
docker compose down -v && ./mvnw spring-boot:run
```

## Configuration

All settings live in `src/main/resources/application.properties`.

| Property | Value | Purpose |
|---|---|---|
| `spring.datasource.url` | `jdbc:postgresql://localhost:5332/postgres-spring-boot` | Used when compose support is absent (jar runs) |
| `spring.jpa.hibernate.ddl-auto` | `update` | Hibernate generates and evolves the schema |
| `spring.jpa.show-sql` | `true` | Logs generated SQL |
| `spring.docker.compose.lifecycle-management` | `start-only` | Leaves Postgres running after app shutdown |

## Tests

```bash
./mvnw test
```

`ApplicationTests.contextLoads` boots the full application context. Spring skips Docker
Compose startup in tests (`spring.docker.compose.skip.in-tests` defaults to `true`), so
**Postgres must already be running** or the test fails to obtain a datasource:

```bash
docker compose up -d db && ./mvnw test
```

## Troubleshooting

**`Connection to localhost:5332 refused`** — Postgres isn't running.
`docker compose up -d db`.

**Port 5332 or 8080 already in use** — find the holder with `lsof -nP -iTCP:8080 -sTCP:LISTEN`,
or run the app on another port: `./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=8081`.

**The endpoint returns `[]`** — the table exists but is empty, and `DataSeeder` only
inserts when the row count is zero. Reset with `docker compose down -v`.

**Duplicate rows after restarts** — shouldn't happen; seeding is guarded by
`repository.count() > 0`. If it does, the table was seeded by something else.

**IntelliJ: `Could not find or load main class com.amigoscode.Application`** — the Maven
module isn't registered. Maven tool window → *Reload All Maven Projects*, then delete and
re-create the run configuration from the gutter arrow next to `main()`.
